Your app's diagnostics and usage logs.
On your server. In your pocket.

Powerbase is a self-hosted telemetry stack. The server ingests batched events, logs and crashes into a single SQLite file; this app puts that data in front of you — dashboards, a log explorer, crash groups, devices and alerts — without a single byte leaving your infrastructure.

Download the signed APK View the source

What it is

Two pieces: a server you run, and this app. The server is one Python process over one SQLite file. The app is the client you actually look at.

You own the data

Everything lands in a file you control. No third-party account, no per-event pricing, no data processing agreement to sign.

Redacted before it is stored

The SDK strips emails, phone numbers, Aadhaar, PAN, card numbers and tokens on the device. The server redacts again on arrival.

Works before you have a server

Demo mode ships on, so every screen is explorable the moment you install it.

Every feature, in detail

Not a teaser — this is the reference for what each screen does.

ScreenWhat it does
Overview Six KPI cards — active devices, sessions, events, crashes, crash-free rate and error-log count — each colour-coded against its threshold. Below them: an events-per-day line chart for the selected range, a ranked list of top screens, a ranked list of top events, and the three most recent crash groups. A banner appears at the top whenever an alert is firing.
Charts The same data at a larger size. Pick the metric (events, sessions, crashes, error logs) and the chart redraws; a total for the range is shown above it. Below, the same range broken down by event name and by screen.
Log explorer Every log line the server holds. Filter by level — any, DEBUG, INFO, WARN, ERROR, FATAL — or search the message text, which runs against the server's SQLite FTS5 index rather than a LIKE scan. Tap any row to expand its stacktrace and context. Each row shows the level, tag, timestamp and originating device.
Crash groups Crashes folded into groups by fingerprint, ranked by how many times each one happened. Each card shows the crash kind (java / native / anr), the occurrence count, how many distinct devices were affected, the first and last time it was seen, and the fingerprint itself. The fingerprint is computed on-device with the same algorithm the server uses, so line numbers and memory addresses do not split a group.
Devices Every install that has reported: manufacturer, model, Android version, app version, session count and last-seen time, newest first.
Alerts Whatever the server's rules are firing, with the severity, the rule name, the threshold it crossed and the measured value. Rules cover the crash-free rate, the error-log rate, an SDK that has gone silent, a failed maintenance job, and rollups that have fallen behind.
Settings See the section below — every control is wired and persists immediately.

Screens

A switch per screen. Turn one off and its tab disappears — the switches really gate the UI rather than sitting there decoratively.

General

  • Language — system, English, Hindi.
  • Notifications.
  • Reset to defaults.

Updates

Check for updates asks the app's GitHub Releases for the latest version and compares it to the one installed. If there is a newer one, Update downloads the signed APK and hands it to the system installer — straight over the installed app, with no browser and no uninstall.

Diagnostics

Log collection is on by default. From here you can see how much has been collected, share it through the system share sheet, export it as .txt, .json, .md or .zip, and clear it. Turning collection off stops new writes but still lets you export and clear what already exists.

Under the hood

  • Full-screen by default — the status and navigation bars are hidden; swipe to reveal them transiently.
  • No third-party libraries for the plumbing — HttpURLConnection for the network, org.json for parsing, and the charts drawn straight onto a Compose Canvas.
  • Read-only — the app holds a read-scoped key. It can never write to your database, and an ingest key cannot read from it.
  • Uncaught crashes are captured into the diagnostics log before the process dies.

Getting started

Ten minutes, from nothing to your own telemetry.

1. Install the app

Download the signed APK from Releases and open it. You will need to allow installing from this source once. The app then keeps itself up to date from inside the app.

2. Look around in demo mode

Demo mode is already on. Every screen is populated with sample data, so you can see what you are signing up for before running anything.

3. Run the server

pip install -r requirements.txt
python scripts/bootstrap.py --app-id com.example.shop --name "Example Shop"
python run.py

Bootstrap prints two keys. Use the read key. An ingest key is write-only by design and cannot read your data back — that separation is what keeps a key embedded in a shipped app from being able to read anyone's telemetry.

4. Point the app at it

Settings → Server → turn demo mode off → paste the server URL and the read key → tap Test connection. You should see Connected — server reports 'ok'.

5. Send it some data

Add the Powerbase Android SDK to the app you want to instrument. It batches events, logs and crashes, buffers them durably on device, and uploads them with exponential backoff — including the crash that killed the app, captured on the way down.

Where Powerbase genuinely wins

  • Compliance without a vendor. If your data cannot leave your infrastructure — health, finance, government, or a client contract that says so — a hosted SDK is off the table. Powerbase is the version you can actually ship.
  • One file is a feature. Backup is copying a file. Restore is copying it back. There is no cluster to keep alive, no version-skew between services, and nothing to page anyone about at 3am.
  • Redaction where it matters. PII is stripped on the device before it is ever written to the local queue. A phone lost in a taxi does not contain your customers' phone numbers.
  • Retention that does not lose the plot. Raw rows are pruned at your retention window, but every day was already folded into a rollup — so the twelve-month chart still works when the twelve-month-old rows are gone. And pruning refuses to delete a day it has not rolled up yet.
  • Honest numbers. The read path tells you whether a chart came from the rollups or the raw tables, so a surprising figure can always be traced to its source.

Where it does not

  • Native symbolication. Crashlytics and Sentry do this properly. Powerbase groups crashes by a normalised fingerprint, which is enough to see what is breaking and how often — not enough to get you a symbolicated libfoo.so frame.
  • Scale. SQLite over one file is excellent for a single product's telemetry and will not replace a warehouse. If you are ingesting billions of events a day, this is the wrong tool.
  • Ecosystem. No integrations with your issue tracker, no session replay, no release health. It is deliberately a small, sharp tool.
The honest summary: if you can use a hosted service and want maximum depth, use Crashlytics or Sentry. If you need the data to stay yours, want to run it on a single box, and care about the app-shaped questions — who is crashing, which screen is slow, is the SDK even still uploading — Powerbase is built for exactly that.

Privacy

  • The app talks only to the server URL you configure. There is no other endpoint in the code.
  • It authenticates with a read-scoped key, which cannot write.
  • Diagnostics logs stay on the device until you tap share or export.
  • No analytics SDK, no third-party crash reporting, no ads, no tracking, no identifiers beyond the install id the Powerbase SDK generates.
  • The only network call the app makes on its own is to GitHub's releases API, and only when you tap Check for updates.

Building it yourself

./gradlew assembleDebug      # debug build
./gradlew assembleRelease    # signed release

Release signing reads KEYSTORE_PATH, KEYSTORE_PASSWORD, KEY_ALIAS and KEY_PASSWORD from the environment, so no key material is ever committed. Pushing a v* tag makes CI build the signed APK and AAB and publish them as a release.
